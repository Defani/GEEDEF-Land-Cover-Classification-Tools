GEEDEF — Land Cover Classification Tools

Google Earth Engine Sentinel-2A SR Harmonized RF | GTB | SVM GEE JavaScript API Universitas Kuningan Updated May 2026

GEEDEF is a cloud-based, interactive land cover classification tool built entirely within the Google Earth Engine (GEE) Code Editor using the GEE JavaScript API. It is designed to accelerate supervised land cover mapping workflows at regional and local scales using Sentinel-2A Surface Reflectance (SR) Harmonized imagery.

The tool integrates three scientifically established machine learning classifiers — Random Forest (RF), Gradient Tree Boost (GTB), and Support Vector Machine (SVM) — operating over a 26-variable feature space composed of 10 native spectral bands and 16 derived spectral indices. The entire workflow, from image compositing and sample digitization to accuracy assessment and GeoTIFF export, is executed server-side on Google's distributed computing infrastructure.

The entire UI is constructed using the native GEE ui module (ui.Panel, ui.Button, ui.Slider, ui.Select, ui.Map, ui.Label, ui.Textbox) without dependency on external frontend libraries such as React or Vue.js.

🚀 Quick Start

Open the tool directly in Google Earth Engine and follow the six-step sequential workflow in the right panel. No local installation is required.

Interface Layout

GEEDEF uses a three-panel side-by-side layout: Left Panel, Interactive Map (center), and Right Panel (control).

PanelFunctionKey Contents
Left Panel Information & Results Active class legend, palette schemes (KLHK / MapBiomas / NLCD), accuracy results (OA & Kappa), per-class area in hectares
Interactive Map (center) Visualization & Digitization Sentinel-2A composites (True Color, False Color, NDVI, NDWI, NDMI, NDBI), sample polygon digitization via GEE Drawing Tools, classified layer rendering
Right Panel Workflow Control Sequential Steps 1–6: ROI, composite acquisition, algorithm selection, class management, classification execution, export
ℹ️ Note on Display Layers

After compositing, the map displays: True Color (B4-B3-B2), False Color (B11-B8-B4), NDVI, NDWI, NDMI, and NDBI. The remaining 10 indices (EVI2, CAI, GCVI, etc.) operate behind the scenes as predictor variables only and are not rendered as map layers.

Six-Step Workflow

All six steps must be executed sequentially. Skipping any step will trigger a warning in the status panel.

1
Define Region of Interest (ROI)
Load or draw the study area boundary

The ROI defines the spatial extent for image collection filtering, classifier training, and area calculation. Two methods are available:

📁 Method A — Load from GEE Asset Dual Refresh in V3.1
  1. Enter your GEE account or project name in the first text field (e.g., ee-defaniarman).
  2. Click 🔄 Refresh Assets to populate the dropdown with available FeatureCollection assets from your project.
  3. Select the boundary SHP from the asset dropdown.
  4. Click 📥 Load ROI from Dropdown.
  5. The map centers on the loaded ROI and displays the boundary as a blue outline.
💡 Asset Path Format

Full path format: projects/ee-username/assets/boundary_name — visible in the GEE Assets panel under Scripts > Assets tab.

✏️ Method B — Manual Drawing
  1. Activate the Drawing Tools from the top-left map toolbar (pencil icon).
  2. Draw a polygon defining your study area boundary.
  3. Click 🖊 Use Map Drawing Tools.
⚠️ Recommendation

For district-scale or larger study areas, Method A is preferred to ensure administrative boundaries match official data. Keep the ROI appropriately sized to avoid computation time-outs.

2
Sentinel-2A Composite Acquisition
Set date range, cloud threshold, and composite method

Builds a cloud-free image composite from COPERNICUS/S2_SR_HARMONIZED according to user-defined parameters.

Acquisition Parameters

ParameterDescriptionDefault
Date RangeStart and end date in YYYY-MM-DD format2024-01-01 – 2024-12-31
Cloud Max (%)Maximum CLOUDY_PIXEL_PERCENTAGE per scene — scenes exceeding this threshold are excluded from the collection20%
Cloud MaskingEnable/disable pixel-level cloud masking via one of three methodsEnabled
Composite MethodTemporal aggregation strategy applied after cloud filteringMedian

Cloud Masking Methods

MethodDescriptionRecommendation
Cloud Score+ Uses cs_cdf layer from GOOGLE/CLOUD_SCORE_PLUS/V1/S2_HARMONIZED; masks pixels with cs_cdf < 0.60 ✅ Recommended — highest accuracy (Pasquarella et al., 2023)
SCL (ESA) Removes SCL classes: cloud shadow (3), unclassified (7), medium cloud (8), high cloud (9), thin cirrus (10), snow/ice (11) ✔ Suitable for most tropical regions
QA60 (Bitmask) Uses bit 10 (opaque cloud) and bit 11 (cirrus cloud) from the QA60 band Simplest but least precise

Temporal Composite Methods

MethodDescriptionBest Use
Median (Default) Pixel-wise median across all scenes in date range Annual mapping; stable and representative
Median Dry Season Selects the lowest NDVI quartile (25% driest scenes) via mean NDVI ranking Maximizing spectral contrast between open land and vegetation
Median Wet Season Selects the highest NDVI quartile (25% greenest scenes) Maximizing vegetation spectral response
🌿 Mangrove Studies

For mangrove mapping, the Median Dry Season composite is recommended to maximize spectral contrast between mangrove canopy and adjacent aquaculture ponds (tambak), which tend to be spectrally similar under wet-season conditions.

3
Classification Algorithm & Parameters
Select an algorithm and tune hyperparameters

Random Forest is an ensemble method that trains multiple independent decision trees on random subsets of data and features. The final prediction is determined by majority voting. Implemented via ee.Classifier.smileRandomForest.

ParameterRangeDefaultDescription
numTrees50–1000500Number of decision trees in the ensemble. Higher values improve stability but increase computation time.
minLeafPopulation1–201Minimum samples per terminal leaf. Lower values produce deeper trees (risk of overfitting).
bagFraction0.3–1.00.5Proportion of training samples used per tree (bagging fraction).

GTB builds trees sequentially, where each new tree corrects the residuals of the previous one. It is generally more sensitive to hyperparameters than RF but can achieve higher accuracy on structured data. Implemented via ee.Classifier.smileGradientTreeBoost.

ParameterRangeDefaultDescription
numTrees50–500200Number of boosting iterations.
shrinkage0.01–0.300.05Learning rate — controls contribution of each tree. Smaller values require more trees but generalize better.
samplingRate0.30–1.00.7Proportion of training samples used per iteration (stochastic gradient boosting).
maxNodes2–105Maximum tree depth per iteration.
loss—LeastAbsoluteDeviationLoss function. LeastAbsoluteDeviation is more robust to outliers than LeastSquares.

SVM finds an optimal separating hyperplane in high-dimensional feature space. Implemented using LIBSVM via ee.Classifier.libsvm. For non-linear data in high-dimensional spectral space, the RBF kernel is generally recommended.

ParameterRangeDefaultDescription
kernelRBF / LINEAR / POLY / SIGMOIDRBFKernel function. RBF recommended for non-linear separability in spectral space.
cost (C)0.1–10010Regularization parameter. High C = tight margin (risk of overfitting).
gamma0.001–2.00.5Influence range per training sample (applies to RBF, POLY, SIGMOID kernels).
degree1–103Polynomial degree — applies to POLY kernel only.
coef00.0–5.00.0Independent coefficient — applies to POLY and SIGMOID kernels only.
⚠️ SVM Grid Search

For SVM with RBF kernel, perform a manual grid search over C and gamma before the final classification run. The default values may not generalize across all study areas and class configurations.

Training / Testing Split

Default 70/30 split. Polygons are randomly divided using GEE's randomColumn method. Use 80/20 for datasets with fewer than 200 samples per class. A minimum of 20–30 polygons per class is required for statistically valid accuracy evaluation.

4
Add Classes & Digitize Training Samples
Define land cover classes and collect training polygons
📥 Option A — Import from SHP Asset NEW in V3.1
  1. Enter your GEE account/project name and click 🔄 Refresh to load available SHP assets.
  2. Select the training sample asset from the second asset dropdown (dedicated to training data).
  3. Click 📖 Read Columns — attribute column dropdowns are automatically populated.
  4. Select the class code column and the class name/label column from the dropdowns.
  5. Click 🔍 Extract Unique Classes — an editable row appears per unique class (name + color).
  6. Edit names and colors as needed, then click 📥 Save & Import Mapped Samples.

Imported samples are merged with any manually digitized samples before classifier training.

💡 Accuracy Penalty Flag

If no field-validated SHP asset is imported and only manual samples are used, the tool applies a −5% correction to OA and Kappa and flags this in the results panel, making the uncertainty of the accuracy assessment transparent.

✏️ Option B — Manual Class Entry
  1. Type a class name in the text field, or click a class from the Left Panel palette for auto-fill (name + hex color are populated automatically).
  2. Edit the hexadecimal color code if needed (e.g., #006400).
  3. Click ＋ ADD CLASS — class codes are assigned automatically and increment sequentially from 0.
  4. The new class appears in the Left Panel legend and the "Select active class" dropdown.

Digitizing Samples

  1. Select the active class from the class dropdown in the Right Panel.
  2. Activate the Drawing Tools (top-left map toolbar, pencil icon) — choose point or polygon geometry.
  3. Draw sample areas on the map for the selected class. Repeat across all classes.
  4. To delete a wrongly placed sample: click the hand/select tool → select the geometry → click Delete from the panel that appears.
⚠️ Best Practice
  • Distribute samples spatially across the study area — do not concentrate all samples in one location.
  • Use multiple small polygons per class to capture within-class spectral variability.
  • Avoid transitional or ambiguous zones between land cover classes.
5
Run Classification
Execute model training and pixel-level mapping

Click 🚀 RUN CLASSIFICATION. The tool executes the following sequence server-side:

  1. Extracts spectral values (26 variables) from all sample polygons via sampleRegions
  2. Randomly splits polygons into training / validation sets using randomColumn
  3. Trains the selected classifier on the training set
  4. Classifies all pixels within the ROI using the trained classifier
  5. Computes the error matrix and derives OA and Kappa from the validation set
  6. Calculates per-class area via ee.Image.pixelArea() in hectares

Accuracy Interpretation

MetricThresholdNote
Overall Accuracy (OA) > 85% Generally accepted threshold for regional land cover studies
Kappa Coefficient > 0.80 "Very Strong" agreement per Landis & Koch (1977) classification scale
⚠️ Low Accuracy Diagnosis

If OA or Kappa falls below acceptable thresholds, consider: (1) adding more samples per class, (2) improving sample quality (avoid ambiguous placement), (3) merging spectrally similar classes, or (4) changing the composite method or date range.

6
Export to Google Drive
Save the classified map as a GeoTIFF
  1. Set the Google Drive folder name (default: GEE_Export)
  2. Set the output filename (default: LandCover_DFRF_V3)
  3. Select the output spatial resolution: 10 m, 20 m, or 30 m
  4. Click ⬆ EXPORT — GeoTIFF to Drive
  5. Monitor progress in the Tasks tab (clock icon, top-right of GEE Code Editor). Click Run on the pending task.
ℹ️ Output Format

Output is a single-band integer raster (pixel value = class code), CRS: EPSG:4326 (WGS84). Compatible with QGIS, ArcGIS, and all major GIS platforms for further analysis.

Tips & Troubleshooting

General Tips

  • Test with a small ROI first before processing large areas to avoid computation time-outs.
  • Use Cloud Score+ as the primary masking method for tropical regions like Indonesia, where thin cirrus and coastal aerosols are common.
  • For mangrove studies, use Median Dry Season composite to maximize spectral contrast between mangrove canopy and aquaculture ponds (tambak).
  • Distribute samples spatially across the study area. Avoid concentrating all samples in one geographic location.
  • For SVM with RBF kernel, perform a manual grid search over C and gamma before the final classification run.
  • Minimum sample size: at least 20–30 polygons per class for statistically valid accuracy evaluation. Use 80/20 split for sparse datasets (< 200 samples/class).

Common Issues

🔴 "Computation timed out"
Reduce the ROI extent; increase scale to 20 or 30 m; shorten the date range to 6 months or less.
🔴 "Not enough pixels in region"
Use 10 m scale or enlarge the sample polygon area. ROI may be too small relative to the selected output scale.
🟡 Overall Accuracy very low (< 70%)
Check sample placement; avoid transitional or spectrally ambiguous zones; add more samples; merge spectrally similar classes; try a different composite method or date range.
🟡 A class is missing from the output map
Ensure all classes have drawn polygons before clicking Run Classification. Classes with no digitized samples are excluded from the classifier.
🔴 Error loading ROI from asset
Verify full asset path; asset must be a FeatureCollection (not a Geometry); check sharing/access settings in the GEE Assets panel.
🟡 Map layer not appearing after compositing
Open Layer Manager (top-right of map); enable all layers; zoom out if ROI is very small. Check that the date range contains images for the selected area.

Cloud Masking Functions

JavaScriptfunction maskByCSPlus(image) {
  return image.updateMask(image.select('cs_cdf').gte(0.60));
}

function maskBySCL(image) {
  var scl = image.select('SCL');
  return image.updateMask(
    scl.neq(3).and(scl.neq(7)).and(scl.neq(8))
       .and(scl.neq(9)).and(scl.neq(10)).and(scl.neq(11))
  );
}

function maskByQA60(image) {
  var qa = image.select('QA60');
  return image.updateMask(
    qa.bitwiseAnd(1 << 10).eq(0).and(qa.bitwiseAnd(1 << 11).eq(0))
  );
}
